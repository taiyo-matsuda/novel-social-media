# 「ちゃんとした小説」の基準

Ballad が AI に書かせる小説と、読む画面の基準。チャット形式やライトノベル調は採らず、文芸として読める長編で溢れるアプリにする（[決定記録 0009](decisions/0009-literary-fiction.md)）。

プロンプトは `packages/core/src/ai/prompts.ts` の `SYSTEM_PROMPT`。この文書を変えたらプロンプトも直す。

## 読者像

読みたいものを読み尽くした大人の本読み。説明されなくても分かる人で、急かされるのを嫌う。

## 文体

- **地の文で語る。** 地の文が全体のおよそ七割以上。会話は場面を動かすところに絞る。会話の行だけが三つ以上続く「台本」の形はなるべく作らない。
- **説明しない。** 感情や性格を「悲しかった」「優しい人だった」と書かず、しぐさ・間・物・光や音で感じさせる。
- **具体的に。** 土地、季節、食べ物、仕事の手順、手ざわり。その場にしかない細部を選ぶ。決まり文句を使わない。
- **緩急。** 文と段落の長さを揃えない。一文ごとに改行して並べる書き方はしない。
- **記号は控えめに。** 「！」「？」「……」「――」は必要なときだけ。笑いの記号・顔文字・語尾のキャラクター付けは使わない。

## 視点と人物

- 視点は作品ごとに決めて守る。一つの場面で視点人物を変えない。視点人物が知りえないことは書かない。
- 文体（だ・である調かです・ます調か、人称、呼び方）は第1章で決め、最後まで変えない。
- 人物には、欲しいもの・隠していること・その人らしい話し方・矛盾を持たせる。善人と悪人に分けない。

## 章の構成

- 1章はおよそ5000〜8000字（`CHAPTER_LENGTH`）。スマホで一度に読み切れ、長編の1章として読みごたえがある長さ。
- 毎章で大事件を起こさない。章末を無理な引きにしない。余韻や静かな問いで閉じてよい。
- 場面転換は「＊」だけの行。アプリが中央に小さく表示する。
- 段落は1行1段落。字下げと段落の間の空行は入れない（アプリが字下げする）。

## 長編での一貫性

前の章をすべてプロンプトに入れるやり方は、章が増えるほど長く高くなり、人物の設定や伏線も埋もれる。そこで、

1. AI は章を書くたびに、本文のあとに **創作メモ**（`【創作メモ】` の下）を書く。作品の芯、登場人物、舞台と決まりごと、章ごとのあらすじ、置いた伏線と未解決の問い、この先の見通し。毎回、全部を書き直す。
2. メモは `works.story_notes` に保存し、読者には見せない（作者本人の生成にだけ使う）。
3. 次の章では、メモと直近2章（`RECENT_CHAPTERS`）の本文だけを渡す。それより前の章はメモのあらすじで把握させる。メモのない古い作品は、これまでどおり全章を渡す。

## 読者の好みと展開リクエストの扱い

- 冒頭文は題材・雰囲気・語り口の手がかり。そのまま使ったり、文章をまねしたりしない。
- 展開リクエストは、作品の芯・人物・文体を壊さない形で取り入れる。一章で急いで片付けない。希望に応えたことを本文で説明しない。
- ジャンルは問わない。ファンタジーや SF でも、世界の決まりごとを解説で並べず、暮らしと行動の中で見せる。

## 読む画面

- 横書きのスクロールを基本に、本のような組み方にする：明朝体、段落頭の一字下げ（会話の「」で始まる段落は下げない）、行間 1.9 前後、1行の長さを抑える（タブレットでも本文の幅を広げすぎない）。
- 章の頭は「第N章」と題を中央に置き、場面転換の「＊」も中央に。
- 縦書きとページめくりは検討中（[決定記録 0009](decisions/0009-literary-fiction.md)）。

## 確かめ方

- `measureStyle`（`packages/core/src/ai/style.ts`）で、字数・段落・会話の割合・会話だけの段落の連続・記号の多さを数える。目安は、会話の割合 3 割以下、会話だけの段落が3つ以上続くのは1章に数回まで、記号は千字あたり 5 以下。
- プロンプトを変えたら `apps/api` で `pnpm sample:chapters <出力先.md>` を実行し、改善前のプロンプト（`apps/api/scripts/legacy-prompt.ts`）と同じ読者で比べる。Claude API を呼ぶので料金がかかる。
