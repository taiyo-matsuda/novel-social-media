# 0002 ログイン方式

- 日付：2026-10-27
- 状態：置き換え済み（[0003](0003-cloudflare-better-auth.md)。Supabase をやめ、メール確認なしのログインにした）

## 決定

- ログインは **メールに届く6桁のコード**（Supabase Auth の Email OTP）。初めての人はそのまま登録になる
- ログイン状態は端末に保存し、次回起動時もログインしたままにする。保存先はネイティブでは `expo-sqlite` の localStorage、Webではブラウザの localStorage
- 登録時に DB のトリガーで `profiles` を自動作成する（表示名は「読者」。メールアドレスは誰でも読める `profiles` に入れない）
- 冒頭文に3つ以上答え、「読みたい」が1つ以上あれば好みを伝え終えたとみなす（`@novel/core/openings`）

## 理由

- パスワードを覚えなくてよい。メールのリンクで戻ってくる方式（マジックリンク）と違い、アプリに戻すためのディープリンク設定が要らず、Expo Go でも試せる
- `expo-sqlite` は Expo Go に入っているので、開発ビルドなしで動く

## 注意

- **Supabase のメールテンプレートを変える必要がある。** 既定はリンクだけのメールなので、Authentication > Email Templates の「Magic Link」と「Confirm signup」に `{{ .Token }}` を入れる（例：`ログイン用のコード：{{ .Token }}`）
- 端末に保存するトークンは暗号化されていない。課金を始めるときは `expo-secure-store` への移行を検討する
- Supabase の標準のメール送信は1時間あたりの送信数が少ない。公開前に独自のSMTPを設定する

## 代わりに検討したもの

- メール＋パスワード：パスワードを忘れたときの導線と、登録確認メールのリンク処理が必要になる
- Apple / Google でログイン：最終的には入れたいが、各社の開発者登録と設定が必要なので後回し（App Store では他社ログインを入れるなら Apple ログインも必須）
